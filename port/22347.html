What is port 22347 used for?

Port 22347 is assigned to wibukey and uses TCP / UDP. The IANA registry describes the service as “WibuKey Standard WkLan”. It sits above the registered range, where most numbers are transient client ports. A fixed high port is worth documenting precisely because tooling often assumes the default.

Ports are the transport-layer address a service listens on. A client that wants to reach wibukey connects to port 22347. A TCP connection is refused when nothing is listening, while a UDP request simply goes unanswered. That is why a port conflict appears whenever two processes try to bind the same number.

Use the commands below to confirm whether port 22347 is actually in use before you change firewall rules. Blocking the port stops new inbound traffic at the firewall, but it does not stop a local process from listening, and it does not remove the service from the machine.

Source: IANA Service Name and Transport Protocol Port Number Registry. Registered assignee: [Wolfgang_Voelker].

Check and block port 22347

Copy-ready commands for the protocols assigned to this port. Run the check first, then block only what should not be reachable.

Check on Linux

sudo ss -tlpn 'sport = :22347' sudo ss -ulpn 'sport = :22347'

Check on Windows

Get-NetTCPConnection -LocalPort 22347 -State Listen -ErrorAction SilentlyContinue Get-NetUDPEndpoint -LocalPort 22347 -ErrorAction SilentlyContinue

Block with UFW

sudo ufw deny 22347/tcp sudo ufw deny 22347/udp

Block with iptables

sudo iptables -A INPUT -p tcp --dport 22347 -j DROP sudo iptables -A INPUT -p udp --dport 22347 -j DROP

These commands are examples for a typical host. Check the listener before you change firewall rules, and persist iptables rules with iptables-save or netfilter-persistent. On Windows, use Windows Defender Firewall or New-NetFirewallRule for persistent blocks. The iptables rules here cover IPv4; mirror them with ip6tables if IPv6 is enabled.

Is port 22347 safe to expose?

Standard/Low

This port is not on our curated list of services with a widely exploited profile. Exposure is only safe when the listening service is intended, patched and protected by a firewall. Keep the listening service patched and remove it if unused. A default-deny firewall policy with explicit allow rules is still the safest baseline.

Common problems with port 22347

Connection refused or timed out

Refused usually means the host is reachable but nothing is listening on port 22347. A timeout more often means a firewall drop, a wrong host or a service bound to a different interface.

Port already in use

Find the process holding the port with sudo ss -tlpn 'sport = :22347' or sudo lsof -i :22347. Stop that process or configure it to bind another port; killing it without identifying it can take down a production service.

Firewall rule did not survive a reboot

UFW and Windows Firewall keep rules across restarts. Raw iptables rules do not: save them with iptables-save or the netfilter-persistent package, and re-apply after upgrades that reset the ruleset.

The port is blocked but still reachable

A firewall rule filters inbound traffic; it does not close the listener. Confirm with the check command above and bind the service to 127.0.0.1 when only local clients need it.

Frequently asked questions

What is port 22347 used for?

Port 22347 (WIBUKEY) uses TCP / UDP. WibuKey Standard WkLan.

How do I check if port 22347 is open?

On Linux run `sudo ss -tlpn 'sport = :22347'` and `sudo ss -ulpn 'sport = :22347'`. On Windows run `Get-NetTCPConnection -LocalPort 22347 -State Listen -ErrorAction SilentlyContinue` and `Get-NetUDPEndpoint -LocalPort 22347 -ErrorAction SilentlyContinue` in PowerShell. If the port is open, the output shows a process listening on port 22347; empty output usually means nothing is bound to it.

How do I block port 22347?

With UFW run `sudo ufw deny 22347/tcp` and `sudo ufw deny 22347/udp`. With iptables run `sudo iptables -A INPUT -p tcp --dport 22347 -j DROP` and `sudo iptables -A INPUT -p udp --dport 22347 -j DROP`. Persist the iptables rules with your distribution's netfilter-persistent or iptables-save tooling so they survive a reboot.
